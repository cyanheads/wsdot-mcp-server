# 0.4.1 — 2026-10-09

## Changed

- **Argument repair** — an integer sent for a string field is accepted as its digits (`stateRoute: 90` → `"90"`, 0.13.9); a numeric string for a number or integer field (`limit: "2"`, `departingTerminalId: "8"`), a boolean string (`remainingOnly: "true"`), and `null` for an optional field (treated as absent) are accepted too (0.13.14). Each was previously rejected with `-32602`; unknown keys are still rejected.
- **Error request ID** ([cyanheads/mcp-ts-core#576](https://github.com/cyanheads/mcp-ts-core/issues/576), 0.13.10) — error results close with `request <id>` and carry `data.requestId`.
- **MCP Registry install entries** ([cyanheads/mcp-ts-core#622](https://github.com/cyanheads/mcp-ts-core/issues/622), 0.13.11) — `server.json` npm entries use `runtimeHint: "npx"` with no `run start:*` package arguments, and the `streamable-http` entry sets `MCP_TRANSPORT_TYPE=http` so it starts the HTTP transport.
- **Docker image** — production dependencies install in a `deps` stage on `$BUILDPLATFORM` with `--os`/`--cpu`, so multi-arch builds no longer run Bun under QEMU ([cyanheads/mcp-ts-core#575](https://github.com/cyanheads/mcp-ts-core/issues/575), 0.13.10); musl-only packages are pruned from the glibc image ([cyanheads/mcp-ts-core#608](https://github.com/cyanheads/mcp-ts-core/issues/608), 0.13.11); the image runs Bun 1.4.2 (`packageManager` too, 0.13.7), creates writable `.cache/` and `.mirror/` directories for the `bun` user, and no longer sets `MCP_FORCE_CONSOLE_LOGGING`.
- **Recovery hints** ([cyanheads/mcp-ts-core#579](https://github.com/cyanheads/mcp-ts-core/issues/579), 0.13.10) — come from each tool's declared `errors[]` contract through the framework's fill, replacing the explicit `ctx.recoveryFor` forwards in the tools and services; the hints callers receive are unchanged.
- **Packaging** — `package.json` gains a `start` script, `start:stdio` / `start:http` run `node dist/index.js`, `test` runs `vitest run`, `dist/*.mcpb` is excluded from the npm tarball, and the `stdio` and `streamable-http` keywords are added. `.gitignore` and `.dockerignore` cover every `.env*` file (`.dockerignore` also the MCP Registry token files), and `.mcpbignore` adds `tests/`, `logs/`, `.cache/`, `coverage/`, and `docs/idea.md`.
- **CodeQL workflow** — runs `actions` and `javascript-typescript` as separate matrix jobs that upload under `/language:<language>`.
- **Framework resync** — framework skills, `devcheck`, `lint:mcp`, `lint:packaging`, `release-github`, and skill-version scripts updated to the 0.13.14 versions; `scripts/install-otel.ts` and `scripts/prune-musl-packages.ts` added for the Docker `deps` stage.

## Documentation

- **README** — the tool reference is condensed to one short block per tool; configuration rows added for `LOG_TOOL_FAILURE_PAYLOADS`, `OTEL_EXPORTER_OTLP_ENDPOINT`, and `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT`; the MCP SDK and Bun badges read `^2.2.0` and `v1.4.2+`.
- **`.env.example`** — framework block adds `MCP_HTTP_MAX_BODY_BYTES`, the log rate-limit, tool-failure-payload, and per-signal OTLP endpoint variables, and a `127.0.0.1` HTTP host default.
- **`CLAUDE.md` / `AGENTS.md`** — framework `^0.13.14` and MCP SDK `^2.2.0` versions, `ctx.inputs`, `ctx.clientCapabilities`, and `ctx.requestId` rows, and the error-envelope and release-PR descriptions.
