# 0.1.12 — 2026-07-11

## Added

- **`wsdot_search_cameras` pagination** — `offset` and `limit` input params (default limit 50, max 500), plus `nextOffset` and `hasMore` enrichment output, so the full filtered camera set is retrievable page by page ([#20](https://github.com/cyanheads/wsdot-mcp-server/issues/20)).

## Fixed

- **`stateRoute` filtering** — `wsdot_search_alerts` and `wsdot_search_cameras` now match on a canonical route number via the shared `normalizeRoute()` helper, so natural forms (`"I-90"`, `"90"`, `"090"`, `"SR 520"`, `"520"`) all resolve and `"90"` no longer substring-matches an unrelated route such as SR 290 ([#17](https://github.com/cyanheads/wsdot-mcp-server/issues/17)).
- **`wsdot_search_cameras` empty results** — a zero-match query renders a `No cameras found.` summary in `content[]` instead of blank text ([#18](https://github.com/cyanheads/wsdot-mcp-server/issues/18)).
- **`wsdot_search_cameras` content parity** — `content[]` and `structuredContent` now carry the identical page; previously every match went to `structuredContent` while `content[]` showed only the first 20, with no path to the rest ([#20](https://github.com/cyanheads/wsdot-mcp-server/issues/20)).

## Dependencies

- `@cyanheads/mcp-ts-core` ^0.10.9 → ^0.10.14
- `@types/node` ^26.0.0 → ^26.1.1
- **`@socketsecurity/bun-security-scanner` ^1.1.2** added — `bunfig.toml` enables Socket install-time scanning plus a 3-day `minimumReleaseAge` supply-chain hold (framework releases excluded).
- **Bun toolchain** pinned to `1.3.14` across the `Dockerfile` build/runtime images and `packageManager`; build-stage `bun install` runs `--ignore-scripts`; `engines.bun` floor relaxed to `>=1.3.0`.
