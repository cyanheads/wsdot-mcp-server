# 0.2.1 — 2026-07-30

## Added

- **Shared HTML-to-text normalizer (`src/services/html-text.ts`).** A hand-written single-pass scanner rather than a dependency — the two framework sanitization helpers are both async, which would make the normalizers async throughout. A destination whose scheme isn't `http`/`https`/`mailto`/`tel` is dropped while the anchor's text is kept; control characters inside a destination are stripped before the scheme check; a destination still carrying an entity this decoder doesn't resolve is rejected rather than passed through.
- **`wsdot_get_ferry_alerts` surfaces bulletin detail.** `alertTitle` (from `AlertFullTitle`), `bulletinText` (the bulletin body, HTML normalized to plain text), `alertType` (e.g. "All Alerts"), and `affectsAllRoutes` (from `AllRoutesFlag`) are now mapped alongside the existing `alertDescription` summary. `bulletinText` is the only place detail such as a replacement sailing appears. `affectsAllRoutes` disambiguates an empty `impactedRouteIds`: `format()` now renders "all routes — this alert affects the whole fleet" when true, and "none listed — this alert names no specific route" when false with no routes ([#34](https://github.com/cyanheads/wsdot-mcp-server/issues/34)).

## Fixed

- **`wsdot_search_alerts` no longer leaks upstream HTML.** `headlineDescription` and `extendedDescription` are normalized to plain text before either response path reads them — an anchor renders as `link text (url)`, keeping the destination. A description that normalizes to nothing is now omitted rather than sent as an empty string. `format()` also puts only the first line of a multi-paragraph headline in the `###` heading, so the trailing alert ID no longer lands mid-paragraph ([#22](https://github.com/cyanheads/wsdot-mcp-server/issues/22)).
