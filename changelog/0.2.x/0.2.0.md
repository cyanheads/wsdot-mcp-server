# 0.2.0 — 2026-07-30

## Changed

- **`wsdot_get_terminal_space` destinations.** `arrivingTerminalName` is removed; the upstream `TerminalName` it mapped is an itinerary string, not a destination, and on multi-stop San Juan itineraries its sibling `TerminalID` names the *departing* terminal, not the arrival. Replaced by `arrivingTerminalIds` (from `ArrivalTerminalIDs`, the terminals actually served — chain straight into `wsdot_get_ferry_schedule`) and `itineraryLabel` (the display string, kept for rendering only). `displayDriveUpSpace`/`displayReservableSpace` are also now surfaced and gate `format()`'s drive-up/reservable lines — `false` means the count isn't reported, not that the lane is empty ([#31](https://github.com/cyanheads/wsdot-mcp-server/issues/31)).
- **`driveUpSpaceCount`/`reservableSpaceCount` floor at zero.** An oversubscribed sailing reports a negative count upstream (confirmed live at `-3`, `-5`, `-6`, `-8`); both fields are now clamped with `Math.max(0, …)` during normalization so the value never reads as usable space, and `format()`'s FULL check is now non-positive (`<= 0`) instead of `=== 0`, extended to `reservableSpaceCount` as well ([#25](https://github.com/cyanheads/wsdot-mcp-server/issues/25)).

## Removed

- **`wsdot_get_ferry_schedule` drops `isCancelled`.** Neither the `scheduletoday` nor `schedule` upstream endpoint has ever populated it — `RawSailing.IsCancelled` was a dead field, so the flag was always absent and the `~~CANCELLED~~` formatter branch was unreachable. The tool description now points callers at `wsdot_get_ferry_alerts` for disruptions (route-scoped, not per-sailing). `wsdot_get_terminal_space`'s `isCancelled` is unaffected — that endpoint genuinely populates it ([#32](https://github.com/cyanheads/wsdot-mcp-server/issues/32)).
